A 2D racing game in which neural-network drivers (11 inputs → 8 → 3) learn to race by neuroevolution: selection and mutation across generations, with no hand-written driving rules. Every result is repeated across random seeds and tested on tracks the drivers never trained on.

What works, what doesn't yet, what I learned

Works

Four tracks, including curved ones built from a centre-line path, plus checkpoints at any angle, a lap-time reward, save/resume, live progress graphs, a start menu and a race-the-champion mode. All 3 technical-track seeds learned a lap (first at generation 28 ± 9), and one of them laps all four tracks. Drivers trained on the flowing track never managed the hairpins (0/5). 25 unit tests pass.

Didn't work yet

A look-ahead input meant to help on hairpins was inconclusive over 3 seeds, so it stays optional until I've run more.

Learned

Fixed-timestep simulation, ray-cast sensors and fitness design. I also learned to inspect a network's inputs and outputs before assuming the physics is broken. One early AI pressed the accelerator and the brake at the same time.

  2. 02SundownHackathon · team of fiveOct 2026

    A Claude Code plugin that gives the working day an ending, built at Claude Code Impact Lab at DCU Innovate (29 Oct 2026). After a set cutoff it holds back new prompts, and a shutdown command leaves a handoff for the next morning. I fixed bugs, tested it and built the presentation slides; a teammate wrote the plugin's core.

    Works

    Sundown is a Claude Code plugin that gives the working day an ending:

    • After your set cutoff, new prompts are held back. You can still send one with override:, and every override shows in your report.
    • /sundown:shutdown pauses any running agent at its next step, and the agent writes a short handoff to TOMORROW.md.
    • The next morning, your first session opens with that handoff.
    • /sundown:report shows your last 7 days (evenings worked, latest finish, prompts held back, overrides), built locally from session timestamps. Prompt text is never stored.
    • It has no dependencies, and its hooks fail open, so a bug can’t lock you out. It includes 95 tests and an optional phone push.

    Didn't work yet

    • It only covers Claude Code, not other editors or terminals.
    • It’s a commitment device, not a lock, so you can override or wake it.
    • An agent stops at its next tool call, so a long command already running (like a ten-minute build) finishes first.
    • The report counts prompts, not hours.
    • It needs Node.js 18 or newer, which the native Claude Code installer doesn’t include.

    Learned

    • I had never used Claude Code before the event. I learned to install it, fix a PATH issue, and log in with a Console account for the API credits.
    • Claude Code hooks (UserPromptSubmit, PreToolUse, SessionStart) let you change how the tool behaves without touching its code.
    • Good tools for burnout work by making stopping the default and continuing a visible choice.
    • Honest limits in the README matter, especially when the project is judged by an agent reading the repo.
